# 阶段评审：标准 MCP 游玩适配

日期：2026-10-24。依据是已合并的规格、工具和传输拉取请求，以及传输拉取请求上的远端检查。本记录接在 [MVP 运行验收](mvp-validation.md) 之后。分数只反映已经跑过的结果。

## 可观察的结果

标准 MCP 客户端现在可以列出已发布故事、开始和读取存档，并提交当前选项。官方客户端在进程内走完《雨夜来信》的两条结局；无法识别的说法、重复的 `requestId` 和过期回合都返回工具错误，存档不前进。`play_turn` 要求照读台词、禁止编造选项、禁止声称已播放声音。

API 进程的 `/mcp` 注册了同一组工具和提示，并对空列表完成了一次真实调用。stdio 在连不上 MongoDB 时失败信息只出现在 stderr，stdout 为空。

没有观察过 Cursor 或其他宿主里的模型是否照做。没有配音、语音识别或小智实机。

## 仍然明显的缺口

1. **目标体验还是文字。** 工具返回的是台词和选项。没有听到角色说话，就不能把产品说成语音游戏。
2. **约束还停在服务端。** 提示词要求模型不要编造，但没有一次真实宿主对话证明模型照读并在被拒绝后停住。
3. **访问范围仍是本地。** 知道会话 ID 就能继续该存档。没有账号、试用记录或付费证据。

下一次最小改动应让一小节故事真正发出声音，或记下一次宿主模型的完整工具对话。在那之前，不因为 MCP 进程能启动而提高产品和商业分数。
