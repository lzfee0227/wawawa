# 模拟器语音与音频阶段评审

日期：2026-10-25。依据 SDD-005、PR #22/#23、本地检查和远端 CI。此阶段把“能听见/能录入/确认后推进”带到创作者模拟器，不把它表述成已经完成的小智设备或无屏幕产品。

## 已验证闭环

- 模拟器分别显示 TTS 和 ASR 来源；没有服务端配置时云选项不可用，浏览器能力按运行环境检测。
- 浏览器 TTS 按角色台词、旁白、当前选项顺序朗读；角色 voiceId 匹配系统 voiceURI/名称，找不到时提示并回退默认声音。
- 浏览器识别和云录音识别都只填写已有选择输入框，必须由作者确认后调用原有 `turnId`、`revision`、`requestId` 选择 API。
- 本地音频文件和 HTTP(S) 地址使用原生播放器；停止、替换、切换回合及卸载清理任务、录音 tracks 和 object URL。
- 服务端配置 OpenAI 兼容 ASR/TTS，密钥只读环境变量；限制文本、录音、响应大小和上游超时，错误不回显上游内容。

分数只反映已经观察到的行为；云兼容协议通过测试不等于任何厂商都可直接使用。浏览器声音和识别服务受设备、权限、网络影响，未配置密钥时不应宣称云能力可用。

## 下一步最小验证

1. 配置一个有权限的 OpenAI 兼容服务，记录中文 ASR 准确率、TTS 首字节延迟、完整回合耗时和失败重试；不要把密钥写入仓库。
2. 在 HTTPS 或 localhost 的两种主流手机浏览器人工验证麦克风权限、停止、打断、后台切换和选项确认。
3. 用一个 5 分钟短篇邀请少量目标玩家试听，记录是否听懂选项、是否愿意重玩、作者制作一条分支所需时间。
4. 有真实证据后再决定是否把云音频缓存、费用配额、MCP/Xiaozhi 播放适配列入下一阶段；当前不扩展 MCP。
