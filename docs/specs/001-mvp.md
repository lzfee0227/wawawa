# SDD-001: 互动音频故事工作台 MVP

状态：实施规格；2026-10-24。目标是在一至两天内验证有状态分支故事的编写—发布—模拟游玩闭环。

## 用户与边界

创作者在本地受信任管理界面编写中文 Ink 剧本，配置角色和声音标识，发布后模拟玩家的口头选择。正式产品面向无视觉游戏体验；MVP 的文字界面是创作和调试工具，不是最终玩家视觉玩法。

本阶段不包含真实 ASR、TTS、多轨音频播放、MCP、小智云联调、支付或多人账户。模拟输入明确标记为“语音识别后的文字”。声音标识是元数据，不代表已合成配音。不做通用聊天和自由生成剧情。

## 验收要求

| ID | 要求 | 验收依据 |
|---|---|---|
| R01 | 创建、读取、编辑保存故事草稿 | 刷新后源码与角色配置保留；保存冲突可见 |
| R02 | 编译 Ink，显示错误与警告 | 错误剧本不可发布；保留原草稿以供修复 |
| R03 | 发布不可变版本 | 每次发布生成新版本；现有会话仍使用原版本 |
| R04 | 输出逐行台词及标签、有效选项 | `speaker`、`emotion`、`audio`、`music` 标签可供后续音频适配器使用 |
| R05 | 按当前有效选项推进 | 支持按钮、中文/阿拉伯数字序号、精确选项文本；模糊/不合法输入提示重选且状态不变 |
| R06 | 长期状态与条件分支 | 示例剧情至少包含好感度、历史flag、隐藏条件选项和不同结局 |
| R07 | 存档与恢复 | MongoDB存完整Ink状态、版本、当前回合；重复读取/重复选项不触发新剧情 |
| R08 | 回合一致性 | 选择请求含turnId、revision、requestId；重复请求只执行一次；过期回合/并发冲突返回409 |
| R09 | 管理与模拟界面 | 编辑器、编译结果、发布、会话恢复、对话日志、当前选项、可折叠调试状态；加载/错误/结束均可辨认 |
| R10 | 可复现质量检查 | 单元/组件覆盖率门槛、Mongo集成、Playwright端到端、键盘/窄屏验证及CI |

## 示例：雨夜来信

林与旁白两种角色。玩家是否保守秘密影响后续可选行动，好感度累计决定同一请求的回应；中间有间隔场景以证明并非只读取最后一次选择。可重复游玩两条路径，比较选项和结局。角色用speaker标签指向角色配置；本阶段在调试界面展示声音ID。

## 业务规则

- 每份session是一份独立游戏存档，不是登录会话。初版以随机ID及浏览器本地引用恢复；知道ID即可访问，不是安全的多租户授权方案。
- 运行到下一个选择点或结束即生成一个回合；回合台词和选项与Ink状态一起原子保存。已计算回合可重放，不重新执行Continue。
- 服务端限制源码长度、标签/角色字段、输入长度和单次执行步数，避免错误脚本无限循环耗尽服务。
- 发布使用服务器已经保存的草稿并校验revision；编译预览可以使用未保存源码，但发布前必须保存。
- 每轮选项生成不透明ID，对应当前Ink choice index。客户端不能指定任意Ink跳转或修改变量。
- 最近8次成功选择保留重试回执；窗口内requestId相同且参数不同应拒绝，同参数返回原有结果。窗口外旧回合返回409，不得再次推进。客户端每次新选择生成新requestId。

## 演示成功标准

从空环境按README启动；编辑示例→编译→发布→玩两条路径→刷新恢复→修改发布新版本→旧会话不变。所有模拟限制在界面显式显示。核心流程在约五分钟内可演示。
