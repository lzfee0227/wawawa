# SDD-004：管理平台基础能力

状态：实施规格；2026-10-25。目标是让现有 Ink 内容能够进入工作台，并可靠地完成“编辑 → 编译 → 发布 → 选择 → 剧情推进”的验证闭环。

## 范围

本阶段只处理本地创作管理能力。MCP、TTS、ASR、设备接入、账号和素材存储保持现状，不新增外部依赖。

## 验收要求

| ID | 要求 | 验收依据 |
|---|---|---|
| R11 | 创建空白故事 | 作者可以创建默认标题、只含注释与 `-> END` 的最小 Ink 模板、空角色列表的草稿，并在编辑器中继续填写 |
| R12 | 导入本地 Ink 文件 | 浏览器选择 `.ink` 或文本文件后，文件名成为初始标题，源码原样导入为独立服务端草稿；不覆盖现有故事，也不自动发布 |
| R13 | 发布状态可辨认 | 故事书架显示草稿修订和更新时间；已加载的故事显示最新发布版本，尚未读取时显示待查看，避免作者误以为只保存等于可游玩 |
| R14 | 指定版本模拟 | 发布记录可以选择某个不可变版本开始模拟；新会话固定该版本 |
| R15 | 真实内容主流程 | 《二哈有福》完整 `story.ink` 可编译，并至少验证开场、三条关系/调查路线和多周目入口能推进到结局 |

## 产品取舍

导入先使用浏览器 FileReader，避免服务端任意文件路径和新的上传存储边界。导入不会自动发布或覆盖其他故事；离开当前未保存内容前需要确认。文件限 `.ink`/`.txt`、400000 字节和 100000 字符，拒绝空内容；失败保留当前编辑内容。复制、删除、批量导入和章节可视化编辑器留到后续阶段。

版本选择只影响新会话，当前会话继续使用原版本。故事列表可继续保留草稿排序，但需补充最新发布状态和更新时间。

局域网 HTTP 的普通模拟器须在 `crypto.randomUUID` 不可用时使用 `crypto.getRandomValues` 生成请求 ID，保证选项提交和角色添加可用。MCP 客户端保持原实现。

## 完成标准

新增组件测试和至少一条浏览器流程；服务端不改变既有 CAS、幂等和版本不可变约束。文档记录已完成 PR、测试结果和仍未实现的声音能力。
